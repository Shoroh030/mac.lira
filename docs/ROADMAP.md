# Дорожная карта «Вместе»

Обновлено: 2026-10-23

## Продуктовые ограничения

- Основной объём пользовательских данных хранить на устройстве; Supabase использовать прежде всего для синхронизации и координации пары.
- Не удалять профили, историю или другие пользовательские данные при тестировании. Тестовые записи чистить только если они однозначно помечены и созданы тестом.
- Debug APK предназначен для локальной проверки, а не для GitHub Release. Обновление Android всегда требует подтверждения в системном установщике; тихая установка невозможна.
- Не публиковать release, пока не подтверждены репозиторий, версия, наличие секретов подписи и совпадение сертификата с уже установленным приложением.

## Готово или реализовано с ограниченной проверкой

- Debug-сборка Android-модуля `together` версии `1.2.8` (versionCode `11`) и `:together:testDebugUnitTest` проходят: 16 unit-тестов, включая проверку кодирования/декодирования Code 128, EAN-13 и QR. Сборка установлена на два подключённых тестовых телефона через `adb install -r`; пакет и сертификат совпадают с установленными копиями, данные приложений не очищались.
- В приложении присутствуют QR/ручной код приглашения, обработка входящих текстовых и графических share-intent, а также базовые онлайн-режимы `connect_four`, `checkers` и `dots_boxes`. Для invite/share utility есть unit-тесты; ранее проводилась базовая проверка парной игры. Полное пользовательское и регрессионное тестирование остаётся открытым.
- Миграция `20261023000100_together_fixes.sql` находится в репозитории. Её применение к удалённому проекту в этой проверке не подтверждалось; не считать удалённый Supabase актуальным без проверки истории миграций.
- GitHub workflow сборки Android release проверяет заданный сертификат и требует секреты keystore. Наличие самих секретов и успешная подписанная release-сборка не подтверждены; GitHub Release не публиковался.
- Профиль сохраняет исходное фото на устройстве, синхронизирует только JPEG-миниатюру в закрытое хранилище пары и кэширует фото партнёра локально; URI/загрузка сбоев не подтверждены вручную на двух аккаунтах. Старые облачные фото не удаляются автоматически.
- Чат сохраняет позицию чтения при обновлении и показывает переход к новым сообщениям; длинное нажатие на своё текстовое сообщение открывает редактирование. Для сохранения изменений требуется применить миграцию `20261023000200_chat_message_edits.sql`; удалённое применение не проверялось.
- В composer добавлены быстрый набор эмодзи и переход к системной клавиатуре, локальный выбор GIF, а для вложений — подтверждение передачи с именем/размером и лимит 12 МиБ. Сжатие не выполняется; сторонний GIF-каталог/API не подключён. Видео-кружки и голосовые требуют явного подтверждения до отправки. Сценарии обмена вложениями между телефонами в этом этапе не проходили ручную проверку.
- Для карт лояльности исправлен маршрут вкладки (раньше открывалась карта партнёра), добавлены ввод и камерное считывание поддерживаемых штрихкодов/QR, общий офлайн-first список и кассовый экран с высоким контрастом, размером и временной регулировкой яркости. Синхронизируются только название, код и формат; фото карты, платёжные данные и CVV не сохраняются. ZXing encoder/decoder проверяется unit-тестами; сканирование физической карты и проверка на кассовом сканере остаются ручным этапом.

## В работе: блокирующие дефекты

### Общий просмотр

- Экран старта комнаты теперь не должен зависеть от необязательной загрузки ссылки на фильм; при ошибке синхронизации показывается состояние/ошибка, а ссылка берётся локально.
- Остаётся блокирующий native crash внутри `libjingle_peerconnection_so.so` при запуске WebRTC. Он воспроизводился на Android 17/API 37 и Android 10/API 29 с WebRTC `150.7871.01`; диагностическая замена на `144.7559.15` также падала, поэтому текущая зависимость восстановлена на `150.7871.01`.
- Причина native abort пока не установлена. До её устранения не подтверждены получение кода комнаты, подключение второго телефона, ICE/SDP, видео после разрешения захвата экрана, чат и штатное завершение комнаты. Не заявлять комнату рабочей по факту успешной сборки.
- Состояние активных тестовых комнат после прошлых запусков отдельно не перепроверялось. Не закрывать неизвестные комнаты и не удалять их сигналы.

### Профиль и аватар

- Базовый offline-first путь и приватная синхронизация реализованы, но полный цикл на двух аккаунтах и восстановление после отзыва доступа/повреждённого файла ещё нужно проверить.
- Добавить целевые тесты на отсутствующий, недоступный и сменённый аватар; проверить profile header, карту партнёра и миниатюры в истории/чате на обоих телефонах.

8. **Оценить отдельное нативное iOS-приложение.** Сначала подготовить платформенный план и требования к сборке/подписи; не начинать rewrite и не публиковать iOS без отдельного решения.

## Проверки и ограничения релиза

- Текущий локальный APK — debug-сборка для тестов; установка через неё не доказывает доступность или корректность release-подписи.
- Release workflow рассчитан на tag `vMAJOR.MINOR[.PATCH]`, проверяет секреты и фиксированный SHA-256 сертификата и требует публичный GitHub-репозиторий для updater. Текущие значения секретов не читаются и не должны попадать в исходники, логи или сообщения.
- Перед следующим release повторно сверить GitHub remote/repository identity, migration history, версию и signing certificate. Если любой пункт нельзя проверить, release не публиковать.

# Дорожная карта «Вместе»

Обновлено: 2026-10-24

## Продуктовые ограничения

- Основной объём пользовательских данных хранить на устройстве; Supabase использовать прежде всего для синхронизации и координации пары.
- Не удалять профили, историю или другие пользовательские данные при тестировании. Тестовые записи чистить только если они однозначно помечены и созданы тестом.
- Debug APK предназначен для локальной проверки, а не для GitHub Release. Обновление Android всегда требует подтверждения в системном установщике; тихая установка невозможна.
- Не публиковать release, пока не подтверждены репозиторий, версия, наличие секретов подписи и совпадение сертификата с уже установленным приложением.

## В работе: блокирующие дефекты

### Общий просмотр

- Экран старта комнаты теперь не должен зависеть от необязательной загрузки ссылки на фильм; при ошибке синхронизации показывается состояние/ошибка, а ссылка берётся локально.
- Причина воспроизводившегося `SIGABRT` в `libjingle_peerconnection_so.so` найдена: `NetworkMonitorAutoDetect` получал `SecurityException` от `ConnectivityService`, поскольку в manifest отсутствовало normal-разрешение `ACCESS_NETWORK_STATE`. Разрешение добавлено в `together/src/main/AndroidManifest.xml`.
- Screen broadcast удалён из комнаты полностью: отсутствуют MediaProjection UI/API, foreground service и связанные разрешения. Камера и микрофон по умолчанию выключены, запрашиваются независимо только после нажатия своих кнопок; плеер и текстовый чат не требуют этих разрешений. Runtime-переключение камеры/микрофона и парная доставка видео ещё требуют проверки с ручным согласием пользователя.
- Экран комнаты перегруппирован вокруг плеера: fullscreen расширяет сам контейнер, скрывает остальные панели и поддерживает выход кнопкой/Back; управление камерой, микрофоном и чатом находится в прокручиваемой области. Встроенный fullscreen YouTube отключён в пользу общей кнопки приложения; `WatchPartyLayoutTest` подтвердил expand/back на Pixel 8 и Huawei.
- Для позднего включения камеры/микрофона joiner запрашивает новое SDP offer через разрешённый базовой схемой сигнал `offer`; запросы host обрабатывает и повторно согласует media-трансиверы. `20261026000100_watch_camera_renegotiation.sql` добавляет совместимость со старым сигналом `renegotiate`; эта схема нужна только клиентам, которые используют именно такой тип. Файл включён в feature branch; этот сеанс не применял его к Supabase, а удалённую историю миграций проверить не удалось. Считать remote state неподтверждённым и не применять без нового разрешения; текущий Android-клиент использует `offer`.
- Сигналы комнаты намеренно игнорируют сообщения с тем же `sender_id`; поэтому host и joiner должны войти под разными аккаунтами. В join flow добавлен явный отказ с объяснением при попытке подключить комнату тем же аккаунтом, а ошибки polling/sending теперь показывают HTTP-код Supabase. Входящие SDP обрабатываются до ICE-кандидатов, чтобы кандидаты новой renegotiation-сессии не добавлялись к старому SDP; порядок фаз покрыт unit-тестом. Парная синхронизация ещё не проверена.
- Добавлен UX приглашения в комнату: отдельная кнопка «Создать комнату» проверяет активные комнаты и не переиспользует старую сессию молча; отдельная кнопка подключения не создаёт комнату автоматически. После создания ведущий получает QR, код, ссылку и системное меню «Поделиться». Второй участник может открыть ссылку, ввести код, отсканировать QR, нажать видимую кнопку «Подключиться» или выбрать активную комнату. Перед входом приложение предупреждает, что статус `active` не подтверждает присутствие host после сбоя, и повторно проверяет активность, пару и владельца. Создание новой при наличии активной требует отдельного подтверждения закрытия старых. Автоматического таймаута/закрытия нет.
- Зафиксирован предыдущий безопасный read-only smoke на 1.3.4/code17: локальная пара совпадала на обоих телефонах, но room ID различался; Huawei получил HTTP 403 при отправке ICE. Политика `watch_signals` требует активную комнату с совпадающими room/couple ID и `sender_id` текущего участника, поэтому это согласуется с выбором неверной/устаревшей комнаты, но точное решение удалённой RLS и актуальное состояние строки не подтверждены. Новый выбор комнаты и предварительная проверка исключают слепое подключение по разным ID, однако исправление 403 и двусторонний media/chat/player smoke ещё не подтверждены парным тестом.
- Локальная финальная проверка `1.3.5` (versionCode `18`): `:together:testDebugUnitTest` — 46 тестов, 0 failures/errors/skipped; `:together:assembleDebug` — успешно. Debug APK проверен (`com.lira.vmest`, подпись Android Debug) и скопирован в `Vmeste-work\APK\together-debug-1.3.5-code18-room-invite.apk`; SHA-256 `70237CA9AD5E21A83E52BB160697C042AD631016F10C4E8080B6756766D03A6D`. Новая версия на устройства не устанавливалась; connected instrumentation не запускался.
- Прямые `adb shell am instrument` прогоны `WebRtcNativeSmokeTest` (150 секунд) и `WatchPlayerRuntimeSmokeTest` (публичные MP4/HLS) прошли на Pixel 8/API 37 и Huawei MAR-LX1H/API 29. Это проверяет локальный WebRTC runtime и подготовку источников, но не парную доставку камеры и не синхронизацию управления между устройствами.
- Gradle `connectedDebugAndroidTest` завершился до запуска тестов (`0 tests`) и удалил `com.lira.vmest` с обоих личных устройств, что могло удалить локальные данные приложения. Удалённые Supabase auth-аккаунты не затрагивались. После согласованной переустановки `1.3.3` read-only проверка показала `local-account-session=false, pair-linked=false`; повторные проверки после сообщений о подключении показали на Pixel 8 и Huawei (`1.3.3`, code 16): файл preferences существует, но ключи `sb_access` и `sb_couple` отсутствуют. Проверялись только наличие файла и имён ключей, токены и идентификаторы не читались. Android Backup данные не восстановил, восстановление связи требует ручного входа в существующие аккаунты и проверки пары. `pm clear` не запускался; camera/RECORD_AUDIO grants сброшены и запрашиваются только после нового ручного согласия. Больше не запускать connected instrumentation на личных телефонах: только emulator/lab с disposable test profile.
- До неудачного runner read-only `WatchRoomSafetyTest` сообщал `active-room-count=0`; после переустановки локальная сессия отсутствует, поэтому повторный запрос списка комнат пропускается. Не выполнять операции закрытия комнат.
- На Huawei scanner crash из logcat был `NoClassDefFoundError` для `androidx.core.content.ContextCompat` из `CaptureManager`; после добавления AndroidX Core class-loading smoke проходит на обоих устройствах. Камерный экран пока не открывали через UI, чтобы не считать class-loading smoke полноценным сканированием.

### Профиль и аватар

- Базовый offline-first путь и приватная синхронизация реализованы, но полный цикл на двух аккаунтах и восстановление после отзыва доступа/повреждённого файла ещё нужно проверить.
- Добавить целевые тесты на отсутствующий, недоступный и сменённый аватар; проверить profile header, карту партнёра и миниатюры в истории/чате на обоих телефонах.
- Кэш удалённого аватара теперь перепроверяет локальную декодируемость и заново скачивает изображение по тому же пути, если кэш повреждён; полученные байты и временный файл валидируются до замены. Решение о повторной загрузке покрыто unit-тестом; парный upload/download не выполнялся из-за отсутствующих локальных сессий на устройствах.

## Следующие этапы

1. **Завершить проверку общего просмотра.** На двух разных существующих аккаунтах проверить приглашение host → кнопку partner → вход в одну и ту же активную комнату, затем синхронизацию YouTube и MP4/HLS, чат без camera/microphone permissions, и вручную проверить двусторонние камеру/микрофон с разрешения пользователя. При повторном HTTP 403 read-only сверить выбранную комнату и удалённую RLS/schema state; не исправлять проблему созданием/закрытием комнат или удалённым применением миграций. Камера/чат/плеер E2E сейчас не подтверждены. Screen broadcast не входит в продукт; для сетей, где STUN не устанавливает P2P, потребуется настроить TURN.
2. **Завершить QR и регистрацию.** QR-приглашение комнаты и сканер реализованы, но физический scan smoke не запускался. Welcome-анимацию проверить на disposable профиле, затем проверить регистрацию, создание пары, сканирование/ввод кода пары, повторный вход и неверный/просроченный код на тестовом стенде; не использовать connected instrumentation на личных телефонах.

## Проверки и ограничения релиза

- Текущий локальный APK — debug-сборка для тестов; установка через неё не доказывает доступность или корректность release-подписи.
- Release workflow рассчитан на tag `vMAJOR.MINOR[.PATCH]`, проверяет секреты и фиксированный SHA-256 сертификата и требует публичный GitHub-репозиторий для updater. Текущие значения секретов не читаются и не должны попадать в исходники, логи или сообщения.
- Перед следующим release повторно сверить GitHub remote/repository identity, migration history, версию и signing certificate. Если любой пункт нельзя проверить, release не публиковать.
